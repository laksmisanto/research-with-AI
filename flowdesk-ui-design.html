Notes / Research / BFS Crawling Architecture
Auto-saved just now
research bdnewsfeed crawler ＋ tag

Overview

The bdnewsfeed scraper uses a multi-layer extraction chain — Trafilatura → Newspaper4k → readability-lxml — with BFS crawling as the discovery mechanism. Each source is crawled on a configurable schedule via APScheduler.

BFS Algorithm

Breadth-first search starts from a seed URL and visits all links at the current depth before going deeper. This ensures broad coverage of a news portal before going into article detail pages.

  • Queue initialized with seed URL per source
  • Each popped URL is fetched, parsed for links, filtered by domain
  • robots.txt compliance checked before each fetch
  • Async fetch via httpx with configurable concurrency limit
robots.txt compliance is non-negotiable — violation risks IP block and legal exposure. Check on every run, cache result for 24h.

Extraction Chain

Articles go through three extractors in sequence. If Trafilatura returns content above threshold, we stop. Otherwise fall through to Newspaper4k, then readability-lxml.

This was the key architectural decision that improved extraction success rate from ~60% to ~94% across 27 sources.
